# 资产提取准确性契约

## 目标

准确性不是让模型声称“很确定”，而是让每项结果都可以回到明确的标准场景和逐字证据，并让不确定结果停在审阅队列。

## 强制不变式

1. **原文不可丢失**：导入文本完整保留；标准化是派生版本。
2. **先标准化后提取**：没有合法 `CanonicalScene` 时禁止资产提取。
3. **完整覆盖**：每个非空原文段落都有唯一 SourceUnit ID；标准化回执必须全覆盖、无重复、无未知 ID。
4. **逐场提取**：模型每次只读取一个标准场景，避免跨场污染人物状态和道具归属。
5. **证据必须逐字存在**：`EvidenceQuote.quote` 必须是对应场景 Fountain 文本的子串；否则整项结果丢弃。
6. **确定性场景与人物入口**：Scene Heading 和 Character 元素由本地解析直接建立候选，不依赖模型是否注意到。
7. **道具定义严格**：道具必须是可采购、制作、陈设或由人物操作的实体；情绪、动作、身体部位和抽象概念不属于道具。
8. **保守合并**：只有同类型且规范键完全相同的资产自动合并；近义名称默认分开等待人工判断。
9. **低置信度不自动确认**：校验置信度低于 0.86 或有警告时必须人工审阅。
10. **审阅决定可追溯**：接受、排除、冲突和编辑均保留在项目文档中。

## 推荐审阅顺序

```text
场景身份
→ 人物姓名与状态
→ 关键道具
→ 材质 / 构图 / 元素
→ 跨场连续性
```

## 常见误提取及处理

| 问题 | 处理 |
| --- | --- |
| 把“门外”“远处”当成独立场景 | 以 Scene Heading 为主身份，动作段落只补充子空间 |
| 同一人物不同称呼被错误合并 | 仅完全规范键自动合并，别名由人工确认 |
| 把“看了一眼”“沉默”当道具 | 类型规则直接排除抽象动作 |
| 把人物伤损状态吞掉 | `continuityState` 独立保存并跨场显示 |
| 模型引用改写后的证据 | 本地 `source.contains(evidence)` 不通过则丢弃 |
| 大文本后段遗漏 | SourceUnit 覆盖回执不完整则标准化失败 |

## 置信度不是最终真相

`validatedConfidence` 只表示证据结构是否可靠，不能替代美术指导判断。特别是以下问题必须人工确认：

- 角色别名和身份揭示；
- 同一地点的不同布景状态；
- 剧情隐含但未明确写出的年代和地域；
- 道具是否需要实际制作；
- 服装是否属于同一套连续性造型。

## 发布验证

- 1000+ SourceUnit 的长剧本分块覆盖；
- 同一场景跨分块合并；
- 中文/英文/混合场景标题；
- Character 与 Dialogue 元素关系；
- 引号、emoji、全角标点和 CRLF；
- 模型遗漏、重复 ID、未知 ID、截断 JSON；
- 低置信度、冲突、排除和重启往返；
- FDX 导入和导出。
